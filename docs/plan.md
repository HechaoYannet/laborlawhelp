# 项目计划与坐标系

本文档定义“我们在做什么、做到哪一步、下一步做什么”，用于研发、产品与 AI 代理统一认知。

## 1. 项目坐标系

### 1.1 产品坐标（价值轴）

- 目标用户：劳动者、中小企业 HR、后续可扩展律师协作侧。
- 核心价值：更快完成案情梳理与风险判断，降低维权与合规沟通成本。
- 关键结果：
  - 劳动者在一次会话内形成可执行行动清单。
  - 企业在一次风险检查内得到优先整改项。
  - 输出内容可直接进入律师复核流程。

### 1.2 业务坐标（流程轴）

- A 轴（劳动者）：咨询 -> 会话建立 -> 流式问答 -> 结构化摘要/文书 -> 分流。
- B 轴（企业端）：风险录入 -> 风险检查 -> 风险等级 -> 整改建议。
- C 轴（交付保障）：可运行 -> 可构建 -> 可测试 -> 可交接。

### 1.3 技术坐标（工程轴）

- 运行坐标：`src/server.ts` + `scripts/dev.mjs|build.mjs|start.mjs`。
- 领域坐标：`src/lib/*.ts`（迁移期回退引擎与基线样例）。
- 交互坐标：`src/app/consultation/page.tsx`、`src/app/hr-risk/page.tsx`。
- 状态坐标：`src/hooks/use-case-store.tsx`（需新增 case/session 双层状态）。
- 协作坐标：`README.md`、`AGENTS.md`、`CLAUDE.md`、本文件。

### 1.4 质量坐标（验收轴）

- Q1 可用性：关键流程可跑通，错误可定位。
- Q2 正确性：规则输出稳定，关键计算可复核。
- Q3 可维护性：职责边界清晰，文档与实现一致。
- Q4 可协作性：AI 工具可快速读取上下文并持续交付。

## 2. 当前阶段判断（2026-04）

- 已达成：
  - 自定义 server 与标准 pnpm 命令链路稳定。
  - 劳动者咨询与 HR 风险两条主流程可用。
  - 文档体系已形成（README/architecture/plan/coze-legacy/agent 指南）。
- 待强化：
  - 当前咨询与风控逻辑仍以前端本地规则为主，未与中间件契约对齐。
  - 前端尚未实现 case/session 双层会话、SSE 真实流式消费、摘要/文书查询链路。
  - 进入“契约优先迁移期”：先对齐 API 与会话模型，再替换主链路实现。

## 3. 里程碑规划

### M0 工程稳态（已完成）

- 目标：让接手者 30 分钟内跑通项目。
- 完成标准：
  - `pnpm install`、`pnpm dev`、`pnpm build` 可执行。
  - 关键入口与命令文档齐全。

### M1 文档与协作规范统一（已完成）

- 目标：多人/多 AI 工具并行时不产生认知偏差。
- 完成标准：
  - 更新 `README.md`、`AGENTS.md`、`docs/architecture.md`、`docs/coze-legacy-and-env.md`。
  - 新增 `docs/plan.md` 与 `CLAUDE.md`。

### M2 API 契约与会话模型对齐（进行中）

- 目标：让前端与中间件在接口层达成一一对应，消除“本地规则主路径”与“服务端编排主路径”的冲突。
- 范围：
  - 对齐 `docs/middlend-plan.md` 的 API 顺序：先 cases/sessions，再 chat SSE，再 summary/document/triage。
  - 前端状态层引入 `case_id`、`session_id`、会话状态、流序号、错误态。
  - 匿名模式下由前端自举 `X-Anonymous-Token`，而不是依赖后端首呼签发。
  - 聊天通信固定为 POST + `text/event-stream` + ReadableStream 解析。
  - 认证采用阶段化：一期游客模式，二期 JWT 强制认证。
- 验收：
  - API 契约文档与实现计划一致，无冲突字段。
  - `src/hooks/use-case-store.tsx` 的状态模型可容纳 case/session 双层、trace_id、tool events 与 final payload。
  - 页面刷新后可基于匿名 token 恢复既有 session 与消息历史。

### M3 咨询主链路后端化（进行中）

- 目标：把咨询主流程从前端本地规则迁移到中间件 + OpenHarness。
- 范围：
  - `src/app/consultation/page.tsx` 由本地打字机模拟改为真实 SSE 流消费。
  - 前端新增 API 客户端层，封装 cases/sessions/chat/summary/document/triage。
  - 本地 `src/lib/calculation.ts`、`src/lib/case-triage.ts` 仅保留回退开关路径（默认关闭）。
- 验收：
  - 咨询主流程默认不再调用本地规则计算。
  - 前端可展示中间件返回的工具轨迹、结构化摘要、引用来源与规则版本。
  - 中断重连后内容顺序与服务端 seq 一致。

### M4 质量与一致性基线（未开始）

- 目标：防止迁移后口径漂移与回归失控。
- 范围：
  - 构建“中间件输出 vs 既有规则样例”对照集。
  - 建立最小冒烟链路：会话创建、聊天流、摘要查询。
  - 保留回退开关演练流程，确保故障时可降级。
- 验收：
  - 关键案例对照误差在可接受范围内。
  - 至少一次完整链路构建验证通过（`pnpm build`）。

### M5 HR 风险接口化（二期，未开始）

- 目标：在不阻塞咨询主链路上线的前提下，完成 HR 风险模块服务化。
- 范围：
  - `src/app/hr-risk/page.tsx` 由本地规则调用迁移到中间件接口。
  - 明确 HR 风险是否复用 case/session，或采用独立风险会话模型。
  - 将 HR 风险工具链纳入 OpenHarness 技能治理与审计。
- 验收：
  - HR 风险页面不再依赖本地规则作为默认主路径。
  - 中间件审计日志可追踪 HR 风险核心调用。

## 4. 角色分工建议

- 产品：定义流程优先级与法律口径更新策略。
- 前端：交互体验、状态管理、可观测性。
- 规则/领域：计算规则、文书模板、风控逻辑维护。
- 工程治理：脚本、构建、环境变量、安全与文档一致性。
- AI Agent：按 `AGENTS.md` 与 `CLAUDE.md` 执行最小充分改动。

## 5. 风险台账

1. 迁移期双轨并存（本地规则 + 中间件结果）可能导致口径不一致。
2. case/session 新模型接入后，前端状态与后端会话可能出现一致性偏差。
3. 游客模式切换到 JWT 强制认证时，历史会话迁移存在用户体验风险。
4. 缺少回归基线时，法律口径调整和 Prompt/Skill 调整难以验证影响面。

## 6. 接手执行顺序（建议）

1. 跑通命令：`pnpm install` -> `pnpm dev` -> `pnpm build`。
2. 阅读文档：`README.md` -> `docs/architecture.md` -> `docs/plan.md` -> `docs/middlend-plan.md`。
3. 先推进 M2 契约对齐，再进入 M3 主链路后端化，避免并行改协议与改实现。
4. 每次提交同步更新相关文档与验收结果。

## 7. 里程碑状态维护规则

- 状态值只用：`未开始`、`进行中`、`已完成`、`阻塞`。
- 每次状态变化必须更新：变更日期、责任人、验证方式。
- 若目标变化，先改本文件与 `docs/middlend-plan.md` 再改实现。
- API 契约字段变更时，必须同步标注影响里程碑（M2/M3/M5）与回退策略是否变化。
