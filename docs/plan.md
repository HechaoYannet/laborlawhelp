# 项目坐标系与里程碑计划

本文档定义项目推进的“坐标系”（如何判断方向是否正确）和“里程碑”（如何判断是否达成阶段目标）。

## 1. 项目坐标系（Project Coordinate System）

### 1.1 X 轴：业务价值

从“可用”到“可信”逐步提升。

1. X1 可用：用户能完成咨询、测算、文书生成。
2. X2 有依据：用户可拿到法规/案例支撑信息。
3. X3 可执行：用户可直接转化为仲裁行动步骤。
4. X4 可复核：法律引用、计算口径可追溯。

### 1.2 Y 轴：工程成熟度

从“功能实现”到“生产级稳定”。

1. Y1 功能接通：链路可运行。
2. Y2 可测试：关键路径有用例与验收清单。
3. Y3 可观测：日志、指标、追踪可定位问题。
4. Y4 可运维：具备灰度、回滚、告警机制。

### 1.3 Z 轴：治理与合规

从“最小约束”到“企业级治理”。

1. Z1 基础：密钥不出前端、输入做基本校验。
2. Z2 增强：来源控制、权限边界、异常分类。
3. Z3 企业级：审计追踪、脱敏策略、合规检查。

## 2. 当前坐标评估（2026-04）

1. 业务价值：X2（已接 MCP 检索增强，仍需提升结果质量控制）
2. 工程成熟度：Y2~Y3（具备类型检查和日志，OTel 导出与告警待完善）
3. 治理合规：Z2（已接入来源/key 守卫，审计与脱敏需继续完善）

## 3. 里程碑定义

### M1：MCP 集成基线完成（已进入）

目标：实现可运行的 MCP 网关主链路。

完成标准：

1. /api/mcp/tools 与 /api/mcp/query 可用。
2. 可通过 pnpm mcp:inspect 校验 sidecar。
3. 咨询页可触发法规/案例增强回复。
4. 出错时可回退到本地流程。

### M2：规则编排质量提升

目标：提高调用准确率，降低空结果与误检索。

完成标准：

1. 建立工具参数模板映射（按工具特征配置）。
2. 增加 20+ 回归样本（法条、案例、流程、边界输入）。
3. 输出结果包含引用来源字段（可核验）。
4. 增加结果评分并过滤低质量输出。

### M3：企业级安全与合规

目标：形成可审计、可追责的服务端治理能力。

完成标准：

1. 接口接入细粒度鉴权策略。
2. 日志落地脱敏与审计字段（traceId/sessionId/operator）。
3. 增加限流和异常流量防护。
4. 完成密钥轮换与环境隔离说明。

### M4：可观测与稳定性

目标：建立生产可运维能力。

完成标准：

1. OTel trace + metrics 全链路打通。
2. 关键指标看板：成功率、P95/P99、超时率、重试率。
3. Sidecar 健康检查 + 异常告警。
4. 完成灰度开关与快速回滚脚本。

### M5：交付与规模化协作

目标：实现多人/多代理无缝接管。

完成标准：

1. 交接文档齐全并通过新人演练（30 分钟启动，1 小时定位主链路）。
2. AI 代理可依据 AGENTS.md 独立完成文档驱动任务。
3. 形成稳定发布节奏（周迭代 + 回归机制）。

## 4. 里程碑节奏建议

1. 第 1 周：M1 收口 + M2 设计
2. 第 2 周：M2 实施 + 回归样本
3. 第 3 周：M3 安全治理
4. 第 4 周：M4 可观测与灰度
5. 第 5 周：M5 交付演练与优化

## 5. 每周固定交付物

1. 本周变更清单（代码 + 文档）
2. 风险清单（新增风险、缓解措施、责任人）
3. 验证记录（ts-check/lint/联调）
4. 下周计划（按里程碑任务拆分）

## 6. 验收总则

1. 所有里程碑必须有“可运行验证步骤”。
2. 所有外部能力必须有“故障回退路径”。
3. 所有关键能力必须有“文档可追溯说明”。
