# 项目计划与坐标系

本文档定义“我们在做什么、做到哪一步、下一步做什么”，用于研发、产品与 AI 代理统一认知。

## 1. 项目坐标系

### 1.1 产品坐标（价值轴）

- 目标用户：劳动者、中小企业 HR、后续可扩展律师协作侧。
- 核心价值：更快完成案情梳理与风险判断，降低维权与合规沟通成本。
- 关键结果：
  - 劳动者在一次会话内形成可执行行动清单。
  - 企业在一次风险检查内得到优先整改项。
  - 输出内容可直接进入律师复核流程。

### 1.2 业务坐标（流程轴）

- A 轴（劳动者）：咨询 -> 提炼 -> 计算 -> 文书 -> 分流。
- B 轴（企业端）：风险录入 -> 规则检查 -> 风险等级 -> 整改建议。
- C 轴（交付保障）：可运行 -> 可构建 -> 可测试 -> 可交接。

### 1.3 技术坐标（工程轴）

- 运行坐标：`src/server.ts` + `scripts/dev.mjs|build.mjs|start.mjs`。
- 领域坐标：`src/lib/*.ts` 规则与计算引擎。
- 交互坐标：`src/app/consultation/page.tsx`、`src/app/hr-risk/page.tsx`。
- 状态坐标：`src/hooks/use-case-store.tsx`。
- 协作坐标：`README.md`、`AGENTS.md`、`CLAUDE.md`、本文件。

### 1.4 质量坐标（验收轴）

- Q1 可用性：关键流程可跑通，错误可定位。
- Q2 正确性：规则输出稳定，关键计算可复核。
- Q3 可维护性：职责边界清晰，文档与实现一致。
- Q4 可协作性：AI 工具可快速读取上下文并持续交付。

  - 劳动者咨询与 HR 风险两条主流程可用。

## 3. 里程碑规划

### M0 工程稳态（已完成）

- 目标：让接手者 30 分钟内跑通项目。
- 完成标准：
  - `pnpm install`、`pnpm dev`、`pnpm build` 可执行。
  - 关键入口与命令文档齐全。

### M1 文档与协作规范统一（已完成）

- 目标：多人/多 AI 工具并行时不产生认知偏差。
- 完成标准：
  - 更新 `README.md`、`AGENTS.md`、`docs/architecture.md`、`docs/coze-legacy-and-env.md`。
  - 新增 `docs/plan.md` 与 `CLAUDE.md`。

### M2 领域服务拆分（进行中）

- 目标：降低页面耦合，形成可测试的应用服务层。
- 范围：
  - 从 `src/app/consultation/page.tsx` 抽离输入提取、回复编排、路由分发逻辑。
  - 保持外部行为不变，先做等价重构。
- 验收：
  - 页面代码体量明显下降。
  - 关键逻辑可被独立单元测试。

### M2.1 演示链路交付（已完成）

- 目标：提供与真实业务隔离的完整前端演示闭环。
- 范围：
  - 首页接入演示入口卡片。
  - 完成 `/consultation?demo=dismiss` 的聊天内硬编码演示脚本。
  - 问诊、摘要、测算、文书、分流建议均在同一对话界面中展示。
- 验收：
  - 不依赖后端即可从首页完整跑通。
  - `pnpm build` 通过。
  - 不影响 `/consultation` 与 `/hr-risk` 原有流程。

### M3 质量基线建设（待启动）

- 目标：建立规则引擎回归保障。
- 范围：
  - 为 `calculation.ts`、`case-triage.ts`、`hr-risk-check.ts` 补测试样例。
  - 建立最小冒烟测试脚本。
- 验收：
  - 关键规则变更可自动发现回归。

### M4 兼容层收敛（待启动）

- 目标：将 Coze 兼容降级为可移除组件。
- 范围：
  - 评估并逐步下线不再使用的 `COZE_*` 变量路径。
  - 输出迁移公告与回滚策略。
- 验收：
  - 标准环境无 Coze 变量依赖。

### M5 智能能力扩展（规划中）

- 目标：在不破坏当前稳定性的前提下引入可控智能能力。
- 范围：
  - 评估外部 LLM/MCP 接入点。
  - 优先服务端集成，确保密钥安全与审计。
- 验收：
  - 新能力可开关、可回滚、可监控。

## 4. 角色分工建议

- 产品：定义流程优先级与法律口径更新策略。
- 前端：交互体验、状态管理、可观测性。
- 规则/领域：计算规则、文书模板、风控逻辑维护。
- 工程治理：脚本、构建、环境变量、安全与文档一致性。
- AI Agent：按 `AGENTS.md` 与 `CLAUDE.md` 执行最小充分改动。

## 5. 风险台账

1. 单页面承载过多逻辑，迭代时容易引入连锁问题。
2. 缺少规则测试时，法律口径调整风险高。
3. 兼容层长期滞留会增加新人理解成本。

## 6. 接手执行顺序（建议）

1. 跑通命令：`pnpm install` -> `pnpm dev` -> `pnpm build`。
2. 阅读文档：`README.md` -> `docs/architecture.md` -> `docs/plan.md`。
3. 选定单一里程碑推进，避免跨里程碑并行改动。
4. 每次提交同步更新相关文档与验收结果。

## 7. 里程碑状态维护规则

- 状态值只用：`未开始`、`进行中`、`已完成`、`阻塞`。
- 每次状态变化必须更新：变更日期、责任人、验证方式。
- 若目标变化，先改本文件再改实现。
